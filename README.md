# 인테리어 협업 플랫폼 — 서버 연결 버전

기존 8766 클론의 메인 페이지를 `/`에 유지하고, 설계안의 업무 화면을 `/app/`에 연결했습니다. 로컬 SQLite로 바로 실행할 수 있으며 PostgreSQL과 비공개 Supabase Storage 연결을 위한 서버 코드·환경 설정·Docker 구성을 포함합니다.

현재 전달 상태는 **로컬 실행 및 기능 검증 완료, 외부 배포 연결 전**입니다. 실제 호스팅 DB·스토리지·도메인·TLS는 아직 연결하지 않았습니다.

- 메인: 기존 클론의 종이 질감, 폰트, 오렌지 포인트, 그리드, 로딩·스크롤·포인터 모션과 자산을 유지했습니다. 진입 링크는 업무 앱으로 연결합니다. 원본 사이트로 폼 내용을 전송하지 않습니다.
- 업무 화면: 같은 폰트·질감·색상·얇은 테두리·도면 모티프를 적용하고 목록, 상세, 폼, 캘린더 등 업무에 맞게 구성했습니다. 메인 페이지와 모든 업무 화면의 레이아웃이 동일하다는 의미는 아닙니다.
- 업무 앱은 한국어 기본/영어 전환과 계정별 PNG 로고 업로드를 지원합니다. 메인 클론의 영어 문구·로고는 보존되어 있으며 업무 앱 언어·로고 설정과 별개입니다.
- 모바일 레이아웃, 키보드 이동, 대화상자, 오류 안내, 이미지 비교 슬라이더, 움직임 줄이기 설정을 반영했습니다. 정식 WCAG 인증을 받은 상태는 아닙니다.

## 처음 실행

Node.js 24 이상이 필요합니다. 새 설치 디렉터리에서 다음 순서로 실행합니다.

```powershell
Copy-Item .env.example .env
npm ci
npm run setup
npm start
```

`npm run setup`에서 최초 회사와 소유자 계정을 만듭니다. 배포 소스에는 기본 계정이나 비밀번호가 없습니다. 기존 `.env`가 있다면 덮어쓰지 마세요.

- 메인: http://127.0.0.1:8766/
- 업무 앱: http://127.0.0.1:8766/app/
- 테스트: `npm test`
- 종료 후 다시 시작해도 `data/`의 DB와 파일은 유지됩니다.
- `APP_ORIGIN`은 실제 주소와 정확히 일치해야 합니다. `localhost`와 `127.0.0.1`은 서로 다른 주소입니다.

검토용으로 현재 실행 중인 127.0.0.1:8766 서버의 가상 계정·프로젝트는 로컬 `data` 디렉터리에 있습니다. `data/`는 Git과 배포 소스에서 제외됩니다. 기존 정적 클론 서버 대신 같은 주소에서 메인과 로그인 API를 함께 제공합니다.

## 서버 및 DB 구성

프론트는 HTML/CSS/JavaScript, 서버는 Node HTTP API입니다. PDF는 PDF.js로 브라우저에서 페이지를 렌더링하고, 업로드 이미지는 서버의 sharp로 실제 디코딩·재인코딩합니다.

로컬 저장은 SQLite입니다. `DATABASE_URL`을 지정하면 PostgreSQL을 사용합니다. 데이터는 종류·ID·업체·프로젝트와 JSON 본문으로 구성된 레코드 저장소에 보관됩니다. 초기 브리핑의 정규화 테이블 설계를 그대로 구현한 것은 아닙니다. 변경은 트랜잭션과 버전 충돌 검사로 처리합니다. 현재 구현은 요청마다 레코드를 읽는 구조이므로 대규모 데이터·다중 인스턴스 운영에 앞서 부하 검증 및 쿼리 최적화가 필요합니다.

인증은 자체 서버 세션이며 Supabase Auth를 사용하지 않습니다. PostgreSQL은 `interior_private` 스키마를 사용하고 공개/anon/authenticated 역할의 직접 접근을 차단합니다. 브라우저별 PostgreSQL RLS가 아니라 서버 API가 사용자·회사·배정·유효기간·공개 여부를 매번 검증하는 구조입니다. 파일 다운로드도 같은 권한 검사를 거칩니다.

필요 설정은 `.env.example`에 모두 있습니다.

| 설정 | 용도 |
|---|---|
| `APP_ORIGIN` | 실제 서비스 HTTPS 주소 |
| `DATABASE_URL` | PostgreSQL 접속 문자열 |
| `POSTGRES_SSL`, `POSTGRES_SSL_CA` | DB TLS 및 필요한 신뢰 CA |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_BUCKET` | 선택한 비공개 파일 저장소 |
| `DATA_DIR` | 로컬 DB·파일 영속 디렉터리 |
| `NODE_ENV` | 운영 환경에서 `production` |

DB·스토리지 비밀키는 서버 환경변수로만 읽으며 프론트에 넣지 않습니다. 서버 배포 키는 선택한 호스팅 서비스의 배포 절차에서 사용합니다. 상세 명령과 백업·복원·복구 절차는 [배포 안내](docs/DEPLOYMENT.md)를 참고하세요.

## 동작 범위와 남은 연결 작업

- PostgreSQL/Supabase/Docker 연결 코드는 포함했으나 실제 서비스 자격증명 및 Docker 실행 환경이 없어 해당 환경에서 검증하지 않았습니다. 배포 후 로그인·업로드·다운로드·재시작 영속성·백업 복원을 다시 확인해야 합니다.
- 초대와 비밀번호 복구는 링크 방식입니다. 자동 이메일/SMS 발송은 연결되어 있지 않습니다.
- PDF 페이지 추출은 암호가 없는 PDF 대상입니다. SKP·DWG는 원본 다운로드와 별도 비교 이미지를 지원하며 브라우저 CAD 편집·3D 렌더링은 포함하지 않습니다.
- 파일당 20MB, 로고 PNG 1MB, 이미지 디코딩 40메가픽셀 한도입니다. CAD/PDF는 형식 헤더 검사를 수행하며 전체 포맷 검증이나 악성파일 검사 엔진은 포함하지 않습니다.
- 한 계정은 전체 서비스에서 하나의 역할을 가집니다. 같은 역할로 여러 회사에 참여할 수 있습니다.
- 로그인 시도 제한은 프로세스 메모리에 있습니다. 여러 서버 인스턴스 운영 시 공유 제한 저장소 연결이 필요합니다.
- 파일을 쓴 뒤 DB 변경이 실패한 경우 참조되지 않는 비공개 파일이 남을 수 있습니다. 자동 정리 작업은 포함하지 않습니다.
- 사용자 입력 콘텐츠의 자동 번역, 운영 관리자 웹 포털, 결제, 공사 완료 승인·작업일지 기능은 포함하지 않습니다.
