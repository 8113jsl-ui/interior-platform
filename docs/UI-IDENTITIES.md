# 화면 식별 체계

대상 페이지: 공개 페이지 26개 및 로그인·PM·고객·현장 화면
대상 영역: 헤더, 내비게이션, 히어로, 본문, 푸터, 폼, 대화상자
대상 요소: 버튼·카드·이미지·텍스트·입력·컨테이너
변경 내용: 안정적인 data 식별자, 이동 목적지 메타데이터, 개발용 오버레이
동작: 실서비스는 메타데이터만 유지. 개발 환경에서만 라벨과 hover 강조 제공.
수정하지 않을 범위: 기존 DOM id, 브랜드 디자인, 원본 모션, 업무 권한 및 로그인 동작

## ID와 관리 파일

- `public/ui/page-registry.json`: 페이지 ID와 실제 경로/업무 화면 패턴. 기존 번호를 변경하거나 재사용하지 않습니다.
- `docs/ui-element-registry.json`: 정적 HTML의 모든 요소 ID, 유형, 구조 키.
- 공개 HTML은 생성 단계에서 data-page-id/data-element-id가 실제 파일에 저장됩니다. 업무 앱은 렌더링·경로 변경 후 동일 규칙으로 부여합니다.
- P01_HOME: 메인, P02_LIST: 자료실, P03_DETAIL: 첫 자료실 상세, P04_LOGIN: 로그인, P05_MYPAGE: 역할별 개인 설정. 다른 개별 글과 업무 화면은 별도 고정 번호입니다.
- 요소 예: `P01_BUTTON_2RCJ8T...`. 순번 대신 64비트 구조 키 해시를 사용하여 문구·언어 변경에 영향을 받지 않습니다. 접두사는 페이지 번호이며 영역도 HEADER/NAV/HERO/CONTENT/FOOTER로 분류합니다. 여러 헤더·영역은 각자 고유 ID를 가집니다.
- 순서가 같은 익명 형제 요소를 구분할 때만 동일 서명 내 순서를 사용합니다. 반복 항목 재정렬이나 구조 이동에도 ID를 유지해야 할 때는 명시적인 `data-ui-key`를 지정하세요. 기존 요소를 이동할 때는 기존 data-element-id도 보존하고 결과를 검토하세요.
- 입력값·사용자 문구·비밀번호는 ID나 레지스트리에 기록하지 않습니다. 기존 PM-01 등의 화면 번호는 보조 정보로 유지합니다.

## 개발자 표시

네임택은 `버튼 01`, `이미지 02`, `헤더 01`처럼 한국어 명칭과 짧은 숫자로 표시합니다. 페이지·요소 유형별 번호이며 같은 브라우저 세션의 새로고침·화면 이동·재렌더링에서 유지됩니다. 화면 표시 번호는 `data-element-key`로 조회합니다. 장기적인 수정 지시에는 페이지와 함께 원래의 `data-element-id`를 사용하세요. 새 브라우저 세션에서는 동적 요소 번호가 달라질 수 있습니다. 글꼴은 네임택 16px, 하단 상태 표시 15px이며, 원래 고유 ID는 변경하지 않습니다.

기본은 꺼짐입니다. `.env`에 `SHOW_ELEMENT_IDS=true`를 설정하고 서버를 재시작하면 활성화됩니다. 개발 환경에서는 `?elementIds=1` 또는 Alt+Shift+I로 켜고 끌 수 있습니다. 설정은 현재 브라우저 세션 동안 유지됩니다. `?elementIds=0`은 끕니다.

오버레이는 닫힌 Shadow DOM에 격리되며 fixed 위치와 pointer-events:none을 사용합니다. 원본 요소의 스타일·레이아웃·포커스·클릭 이벤트를 변경하지 않습니다. aria-hidden으로 읽기 도구에 노출하지 않습니다. 네임택은 요소 위쪽에 배치하며 겹칠 때 밀집 태그를 숨기고 hover한 요소의 라벨과 테두리를 우선 표시합니다. 모든 ID는 표시 밀도와 무관하게 data 속성에 유지됩니다.

`NODE_ENV=production`에서는 서버 설정과 관계없이 오버레이를 비활성화합니다. 개발 단축키·URL 옵션·저장된 설정도 무시됩니다. CSS 디버그 스타일은 오버레이 내부에만 있습니다.

개발 콘솔에서 `UIIds.page`, `UIIds.inspect()`, `UIIds.find('요소ID')`로 조회할 수 있습니다. `UIIds.setEnabled(true)`도 서버가 개발 환경일 때만 허용됩니다.

## 이동과 수정

실제 href를 기준으로 내부 이동에 data-target-page와 data-action="navigate"를 추가합니다. 기존 data-action이 있으면 유지하고 data-ui-action="navigate"를 사용합니다. 외부 링크와 현재 페이지 내부 앵커를 다른 화면으로 잘못 표시하지 않습니다. 링크 목적지나 클릭 처리 코드를 이 기능이 바꾸지 않습니다.

새 공개 페이지/요소를 추가한 후 `node scripts/build-ui-identities.mjs`를 실행하세요. 원본 페이지 동기화도 마지막에 이 단계를 실행합니다. 자동 생성된 번호는 검토 후 저장소에 함께 커밋합니다. 새 업무 화면은 기존 `screen-registry.js`와 페이지 레지스트리를 함께 갱신합니다.

수정 요청은 AGENTS.md의 여섯 항목(대상 페이지·영역·요소·변경 내용·동작·수정하지 않을 범위)으로 기록합니다.

## 검증 결과

- 70개 페이지/패턴, 공개 HTML 요소 24,940개 등록. 전체 레지스트리의 ID 중복 없음.
- 빌드 반복 실행 후 메인 HTML 해시 동일.
- 브라우저 가격 화면 1,862개 런타임 ID 중복 없음. 네임택 on/off 전후 제목 좌표와 문서 크기 동일.
- PM 목록의 12개 버튼 ID는 한국어→영어→한국어 전환에서 유지됨.
- PM 목록에서 개인 설정으로 실제 이동하면 P05_MYPAGE로 변경됨. 목록 179개 및 개인 설정 116개 런타임 ID 중복 없음.
- 운영 설정에서는 개발 표시 옵션이 true여도 서버가 false를 반환함. 테스트 포함 총 62개 통과.

표시량이 많은 페이지에서는 가독성을 위해 기본 네임택을 최대 35개까지 간격을 두고 표시합니다. 컨테이너·밀집 요소도 data ID는 모두 보유하고 있으며 hover 하단 상태 표시와 `UIIds.inspect()`에서 확인할 수 있습니다.
