# 인테리어 플랫폼 디자인 시스템 분석 및 적용안

분석일: 2026-09-17. 참고: https://heronaiapp.com/

상태: 참고 페이지 DOM·CSSOM 분석과 로컬 UI 프로토타입 작성 완료. PNG 로고 교체, 기본 한국어 및 영어 전환 반영. 신규 브랜드색은 확정하지 않고 무채색 중심으로 재해석했다. 실제 서비스의 인증·권한·서버 저장은 별도 범위다.

## 1. 근거와 범위

사용자가 제공한 `인테리어플랫폼_뎁스구조_설계안_0917.md`와 `인테리어플랫폼_화면구조도_0917.html`을 요구사항 자료로 검토했다. HTML은 서비스 화면 구현물이 아니라 역할별 구조도와 설명용 비교 슬라이더다. 문서 10절의 개발 AI 지시문은 자료에 포함된 구현 기준이며, 사용자의 별도 배포 지시나 보류 정책 승인으로 간주하지 않는다. 원본 PDF는 제공되지 않았으므로 대조하지 않았다.

참고 사이트는 브라우저에서 실제 DOM, 계산 스타일, 연결된 스타일시트 규칙과 스크립트 목록을 확인했다. 아래에는 확인한 사실과 신규 제안을 분리했다. 사이트 전반의 모든 상태·스크립트 실행을 감사한 결과는 아니다.

## 2. 구조 분석 요약

참고 페이지에는 header 1개, main 1개, section 8개, footer 1개가 있으며 별도 nav 요소는 없었다. 탐색 영역은 div·링크·버튼으로 구성된다. 본문은 대형 비주얼과 제목, 소개, 문제 제시, 사용 흐름, 제품 소개, 장점, 대상 사용자, 마지막 행동 유도 영역으로 이어진다. 시각적으로는 얇은 경계선으로 영역을 나누고, 넓은 이미지 영역과 압축된 정보 패널을 조합한다.

공통 `.container.grid`는 데스크톱에서 12열 CSS Grid를 사용하고, 내부 메뉴·카드에는 Flexbox가 혼합된다. 관찰한 컨테이너의 max-width는 100%였다. Webflow 기본 컨테이너 규칙도 존재하지만, 이를 실제 페이지의 고정 1200px 컨테이너라고 해석하면 안 된다. 767px 이하에서는 공통 그리드가 4열로 바뀌고 여러 요소가 세로로 재배치된다.

우리 플랫폼은 이 홍보 페이지의 섹션 순서를 가져오지 않는다. 설계안의 `D1 업무 → D2 프로젝트 → D3 기능 → D4 항목`을 유지하고, 그리드 정렬·선 중심 구획·낮은 장식 밀도만 업무 화면에 적용한다. 프로젝트 목록 위에 현황을 배치하고 별도 대시보드 메뉴는 추가하지 않는다.

## 3. 추출 토큰

아래 변수명은 분석용으로 새로 정리했다. 값은 참고 CSS에서 확인했으며 신규 브랜드 팔레트 확정안이 아니다.

```css
:root {
  --reference-accent: #fa3600;
  --reference-primary: #282828;
  --reference-secondary: #414140;
  --reference-tertiary: #282828b8;
  --reference-border: #b3b3af;
  --reference-disabled: #b4b4b0;
  --reference-surface-gray: #72726f;
  --reference-granite: #626260;
  --reference-white: #ffffff;
  --reference-font: "BT Grotesk", Arial, sans-serif;
  --reference-border-width: max(1px, .1rem);
  --reference-menu-duration: 400ms;
  --reference-menu-easing: ease;
}
```

- accent는 주요 행동과 표시점, primary·secondary는 텍스트, border는 구획선에 쓰인다. 변수 이름의 surface-gray가 페이지 전체 배경이라는 뜻은 아니다. 화면 배경에는 이미지 텍스처가 결합되어 있어 단일 HEX로 확정하지 않았다.
- 본문 계산 스타일은 weight 500, line-height 1.3, letter-spacing 약 -0.02em. 관찰 시점에 본문 약 11.85px, H1 약 41.48px/700, H2 약 35.56px/600, 일부 소제목 약 29.63px/600이었다. 이는 해당 뷰포트의 계산 결과이며 고정 px 토큰이 아니다.
- CSS에서 태블릿 제목 7.2/4.8/4/3.2/2.8/2.4rem, 모바일 제목 4/3.2/2.4/2/1.8rem 규칙을 확인했다. 태블릿 html font-size는 1.19904vw, 모바일은 2.54453vw로 지정되어 rem도 가변적이다.
- 0.8/1.2/1.6/2.4/3.2/4.8/6.4rem 간격이 반복되며, 1/1.4/2rem 및 보정값도 공존한다. 엄격한 8px 배수 체계라고 단정하지 않는다.
- 조사한 주요 섹션·컨테이너는 radius 0, shadow none. 전체 컴포넌트가 동일하다는 보장은 아니다.
- main의 z-index 2, header의 10000000, 일부 고정 요소의 4·10을 확인했다. 정돈된 레이어 토큰 체계보다는 개별 조정에 가깝다.
- 폰트명은 분석 사실로만 기록한다. 해당 폰트 파일과 배경 텍스처를 신규 코드로 복사하지 않는다.

## 4. 인터랙션 및 CSS 아키텍처

메뉴 펼침은 opacity·grid-template-rows 또는 clip-path를 활용하며 0.4초 전환 규칙이 있다. 데스크톱 버튼은 겹친 두 라벨을 세로로 이동하고 아이콘을 가로로 교체한다. 카드 hover에는 제목 이동, 점·기호 노출, SVG 선 그리기 애니메이션이 연결된다. SVG 애니메이션은 대략 0.3~0.9초의 개별 구간과 지연을 조합하며, 정확한 전체 easing은 추가 확인이 필요하다.

GSAP, ScrollTrigger, SplitText, Lenis, Barba, Swiper 스크립트가 연결되어 있다. 이는 해당 라이브러리의 연결 사실이며 모든 효과의 실제 실행을 입증하지 않는다. CSS에 sticky 구성, 활성 상태별 노출, 모바일 Swiper 상태 연동이 존재한다. 일부 SVG 효과에는 prefers-reduced-motion 예외가 있지만 전체 사이트의 동작 감소 대응이나 키보드 접근성을 보증할 수 없다.

Webflow 생성 클래스(`w-container`, `w-node-*`)와 의미 기반 컴포넌트 클래스, `.grid`, `.txt`, `.tb-*`, `.mb-*` 같은 유틸리티·조합 클래스가 혼합된다. 엄격한 BEM 또는 Tailwind라고 분류하지 않는다. 주요 반응형 경계는 991/767/479px이며, hover 지원과 992px 이상 조건도 사용한다.

## 5. 설계안 적용 기준

| 영역 | 진입점 및 구성 | 유지할 경계 |
|---|---|---|
| 디자이너/PM | 프로젝트 목록, 고객 관리, 전체 캘린더, 변경이력 | 알림은 공통 버튼, 설정은 보조 메뉴 |
| 프로젝트 | 개요 + 도안·시안/자재/고객 요청/시공 사진/일정/견적서 + 설정 | 개요·설정을 6개 업무 탭과 구분 |
| 고객 | 내 프로젝트 → 프로젝트 홈 및 공개 업무 | 공개 범위와 허용 행동만 노출 |
| 시공팀 | 현장 사진 및 배정 현장 필터 | 첫 화면 확정은 문서상 제안 상태 유지 |
| 개별 상세 | 도안·자재·요청·사진·일정·견적서 | 폼·수정·필터 때문에 D5를 추가하지 않음 |

PM-14 비교는 고정된 동일 크기 영역에 두 이미지를 겹친다. 0%는 B 전체, 50%는 좌측 A·우측 B, 100%는 A 전체다. 비율 조작 시 이미지 크기는 유지하고 노출 영역만 바꾼다. 마우스·터치·키보드, A/B 선택과 라벨, 비율 표시, 부족한 이미지와 로딩 실패 상태를 포함한다. SKP·DWG 원본을 이미지로 취급하지 않으며 PDF는 페이지 미리보기와 연결한다.

신규 코드는 원본과 독립적인 시맨틱 header/nav/main/section/footer 및 표·폼 구조로 작성하는 것이 적합하다. 모바일 업무 탭은 가로 스크롤, 데이터 목록은 의미가 보존되는 재배치 또는 명시적인 표 스크롤을 사용한다. 본문 최소 16px 수준과 충분한 한글 행간, 명확한 focus-visible, 상태 텍스트, 폼 오류 안내, 동작 감소 대응을 제안한다. WCAG 2.1 AA 충족 여부는 구현 이후 실제 색 대비·키보드·확대·오류 흐름을 검증해야 한다.

## 6. 구현 방식 제안 및 미결정

원래 요청한 전체 HTML/CSS 산출물에 맞춰 **순수 HTML/CSS/JS의 로컬 UI 프로토타입**을 권장한다. 브라우저에서 파일을 열어 화면 전환과 비교 동작을 검토하기 쉽다. React는 재사용 컴포넌트와 장기 개발에 유리하지만 개발 환경이 추가된다. 서버와 인증까지 포함하는 실서비스 구현은 현재 요청의 UI 코드 산출과 별도의 범위로 구분해야 한다.

신규 제품의 브랜드명·팔레트·톤·스택은 두 문서에서 확인되지 않는다. 임시 문서 제목 사용과 시각 방향 제안 허용 여부를 사용자에게 질문했다. 실제 프로젝트명·고객명·수량·가격·사진을 임의로 생성하지 않는다. 데이터 미제공 화면은 빈 상태로 만들 수 있으며, 설명용 샘플이 필요하면 허용 여부를 확인한다.

문서상 보류 사항은 업체 설정 권한, 초대·배정 위치, 코드 없는 고객 확정 방식, 도안 이전 버전 정책, 시공 완료 연동 등이다. 보류 상태를 유지하면 UI 시안 제작은 가능하므로 모두를 이번 단계에서 결정할 필요는 없다. 시스템 관리자·결제·고객 마이페이지·확정 코드 페이지·시공 일지를 새로 추가하지 않는다.

## 7. 재해석 방향과 다음 검증

- 참고의 12열 정렬과 선 중심 구획 → 업무 목록·상세 패널에 적용.
- 과감한 영문 홍보 제목 → 읽기 편한 한국어 업무 제목과 상태 체계로 변경.
- 스크롤 중심 연출 → 필요한 버튼·탭·상태 전환에 짧은 반응으로 축소.
- 참고 브랜드색·로고·폰트 파일·사진·텍스처 → 신규 브랜드 결정과 자체 코드로 교체.
- 과도한 z-index → 고정 메뉴·팝오버·모달의 작은 명시적 레이어 체계로 정리.

구현 후 화면 ID별 목록→상세→뒤로가기, 직접 링크·새로고침, 반응형, 슬라이더 0/50/100%, 키보드 동작, 빈 상태를 확인한다. 프론트엔드 데모에서 서버 권한·저장·실제 업로드가 검증된 것으로 보고하지 않는다.

현재 검증 상태: 입력 문서와 참고 스타일 조사, UI 코드 작성, 로직/HTML 생성 자동 검사 15건 통과. 주요 텍스트 색상 대비 5.25:1 이상 확인. 브라우저 시각·터치·스크린리더 검증과 종합 WCAG AA 검증은 미실시. 구현 범위와 보류·미구현 화면은 interior-platform/README.md에 기록했다.


## 8. 최종 산출물과 재해석 토큰

- `인테리어플랫폼.html`: 전체 코드가 들어 있는 단일 실행 파일.
- `interior-platform/index.html`, `styles.css`, `core.js`, `app.js`: 역할별로 분리한 편집용 전체 소스.
- `interior-platform/README.md`: 실행·로고·언어·저장 안내, SCREEN_ID 대응과 한계.

```css
:root {
  --color-ink: #282828;
  --color-secondary: #50504c;
  --color-muted: #66665f;
  --color-paper: #f5f4ef;
  --color-surface: #fffefa;
  --color-line: #cecec5;
  --color-strong-line: #85857b;
  --color-focus: #185c93;
  --color-positive: #28613e;
  --color-danger: #a12720;
  --font-sans: Arial, "Malgun Gothic", "Apple SD Gothic Neo", sans-serif;

  --space-4: 16px; --space-6: 24px; --space-8: 32px;

  --z-header: 10;

```

이 값들은 신규 UI용 제안 값이며 참고 사이트의 추출 값과 구분한다. 원본의 주황색 브랜드 강조는 채택하지 않았고, 포커스·성공·오류 색상은 기능적 상태 표시다. 메뉴 선택은 색상뿐 아니라 밑줄/굵기, 상태는 텍스트로 구분한다. UI 전환은 180ms이며 reduced-motion에서 제거한다. 데스크톱은 목록 8/보조 4 비율, 모바일은 단일 열로 전환한다.
