# UI 재구성 적용 내역 — 2026-09-18

현재 실행 화면은 `/app/`입니다. 기존 루트 `/`의 참고 사이트 클론을 유지하면서, 업무 앱의 화면 구성을 새로 만들었습니다. `public/app/reference-ui.css`, `workspace-ui.js`, `motion.js`가 이번 적용의 중심입니다.

## 입력 자료의 적용 순서

사용자가 “100% 가이드라인”으로 지정한 붙여넣은 브리핑을 기능 기준으로 삼았습니다. SITE_DESIGN.md와 SITE_STRUCTURE.md는 보조 자료로 사용했습니다. 후자의 4역할·별도 Next.js 저장소·금색 버튼·구매 관리와 브리핑의 3역할·6개 업무·Heron 스타일이 충돌하는 부분은 브리핑을 우선했습니다. 따라서 PM·고객·현장 구조를 유지하며 별도 운영자 콘솔이나 구매 업무를 임의로 추가하지 않았습니다.

서비스 표시명은 첨부 SITE_STRUCTURE.md의 ‘인테리어 서포터’를 사용합니다. 업무 앱의 PNG 로고 교체와 한국어/영어 전환을 유지합니다. 사용자 입력을 번역하거나 임의의 실제 업체·시공 사례로 채우지 않습니다.

## 디자인 적용

참고 페이지와 보관된 CSS에서 확인한 종이 배경, 잉크색 텍스트, 가는 격자선, BT/Geist 서체, 주황색 강조, 모서리 좌표, 도면 모티프, 분할 캡션 구성을 적용했습니다.

```css
:root {
  --color-ink: #282828;
  --color-muted: #626260;
  --color-bg: #efeee7;
  --color-soft: #e4e4db;
  --color-line: #b3b3af;
  --color-strong-line: #72726f;
  --color-accent: #fa3600;
  --color-focus: #b12b08;
  --font-sans: BT, 'Malgun Gothic', 'Apple SD Gothic Neo', sans-serif;
  --font-mono: Geist, 'Courier New', monospace;
  --radius: 0;
  --shadow: none;
}
```

라틴 문자는 보관된 BT 400/500/600/700 및 Geist 500 파일을 사용합니다. 한국어 글리프는 OS 한국어 폰트로 보완합니다. 주황색 버튼의 작은 글자는 #161616으로 조정하고 입력창 경계는 강한 선 색상을 적용했습니다.

| 화면 | 적용한 구성 |
|---|---|
| 로그인·복구 | 왼쪽 도면/문구, 오른쪽 인증 폼의 분할 프레임 |
| 프로젝트 목록 | 넓은 도면 영역 → 제목·설명·CTA 분할 → 4개 요약 수치 → 프로젝트 행 |
| 프로젝트 개요 | 프로젝트 제목·상태·기간·전환, 고정 업무 탭, 고객 홈 영역 |
| 도안·견적 | 번호·미리보기·설명·공개 상태·등록 정보를 가진 문서 목록 |
| 자재 | 이미지/빈 이미지 상태, 공간·사양·공개·확정 상태 카드 |
| 시공 사진 | 사진 중심 앨범과 공정·촬영일·업로더 정보 |
| 요청 | 요청 목록과 원문/추가 정정/답변 상세 |
| 일정 | 일요일 시작 월간 캘린더, 시간 범위를 표시하는 타임라인 |
| 고객 관리·이력·알림 | 동일한 제목·선·목록 체계와 정규 상세 연결 |
| 등록·편집 | 원래 화면의 맥락을 남기는 우측 패널, 필드 레이블과 저장 오류 |

도면 그래픽 `assets/studio-plan.svg`는 새로 작성한 장식용 벡터이며 실제 프로젝트 도면이 아님을 표시합니다. 자료가 없는 프로젝트에 가짜 사진을 넣지 않습니다.

모션은 버튼 글자 롤링(0.4초), 목록 등장(0.65/0.8초), 미세한 도면 포인터 이동, 좌표 커서, 스크롤 진행선, 우측 패널 진입으로 구성합니다. 스크롤을 가로채지 않으며 `prefers-reduced-motion`에서는 이동 효과를 끕니다. 포인터 커서는 클릭·입력 대상 위에서 숨깁니다. 1200/991/767px에서 그리드를 조정하고 모바일 탭만 부분 가로 스크롤합니다.

브리핑에 따라 업무 앱의 반복 사용을 방해하는 긴 인트로를 넣지 않았습니다. 모든 업무 화면을 마케팅 페이지와 같은 화면으로 만들거나 모든 애니메이션 프레임의 픽셀 일치를 측정한 구현은 아닙니다.

## 브리핑과 기능 연결

| 기준 | 현재 연결 방식 |
|---|---|
| PM 시작 화면 | 프로젝트 목록. 별도 중복 대시보드 없음 |
| 깊이 | 1단계 역할 목록 → 2단계 프로젝트 컨테이너 → 3단계 탭 → 4단계 항목 상세 |
| 화면 레지스트리 | `screen-registry.js`와 `docs/screen-registry.json`. 렌더된 main에 `data-screen-id`, `data-depth` 표시 |
| 고객 프로젝트 | 배정과 공개 조건을 서버에서 적용하고 업체별 그룹 표시 |
| 현장 계정 | 미배정/단일/복수 현장 분기. 사진 업무와 서버 지정 업로더 유지 |
| 고객 홈 | 문구와 4개 영역의 순서·표시 여부를 저장. 원본 자료를 참조하며 복제하지 않음 |
| 고객 홈 미리보기 | 공개 프로젝트·자료·공개 시점 이력만 표시. 내부 행위자 정보 및 편집 버튼 제외 |
| 도안 | 원본 PDF/SKP/DWG, 별도 비교 이미지, PDF 페이지 PNG 추출, 같은 프로젝트의 A/B 비교 |
| 비교 실패 | 이미지 미선택/동일 선택, 디코딩 실패, 접근권한 상실 안내 분리 |
| 자재 | 카테고리·공간·검색어를 각각 적용. 공개 여부와 확정 상태 분리 |
| 요청 | 원문 보존, 정정 추가, 담당자 답변 및 처리 상태 |
| 사진 | 공정·촬영 시작/종료일·업로더 필터. 여러 장 업로드의 부분 성공 유지 및 재시도 |
| 일정 | 시작일/시각·종료일/시각 저장, 날짜 전용 일정 허용. 실제 달력 날짜 및 역전 범위 검증 |
| 시간 기준 | Asia/Seoul. 한국어/영어 날짜 표시는 바꾸되 저장된 달력 날짜를 이동시키지 않음 |
| 견적 | 원본 파일 보존, 버전 묶음, 버전별 변경 설명·공개 상태 |
| 서버·권한 | 세션, 업체/프로젝트 배정, 파일 접근, 공개 상태, 변경 버전 충돌 검사 유지 |
| 저장 | 서버 검증 → 트랜잭션 변경 → 이력/알림 → 응답 → UI 갱신 |
| 공통 설정 | PNG 로고, 메뉴 언어, 소유자용 회사/참여자/확정 정책 설정 |

순서 설정은 `projects.homeSections`에 저장되며 허용값은 `overview`, `recent`, `schedule`, `resources`입니다. 중복과 알 수 없는 키는 서버에서 거절합니다. 폼의 비어 있는 선택 시각/종료일은 없는 값으로 정규화합니다. 일정에는 유효한 시작일이 필요합니다.

## 검증과 남은 외부 연결

현재 자동 테스트와 브라우저 검증 내용은 `VERIFICATION.md`에 기록했습니다. 브라우저 확인에 사용한 프로젝트·일정·자재는 별도의 로컬 검증 데이터이며 배포 ZIP에 포함되지 않습니다.

초대·배정·확정은 구현되어 있지만 미결정 정책을 자동 활성화하지 않습니다. 회사 소유자의 설정이 필요합니다. 배포 키와 DB 키를 받지 않아 외부 PostgreSQL, Supabase Storage, 호스팅 및 자동 메일 발송은 실제 연결·운영 검증 전입니다. 실행 코드와 환경변수/Docker/백업 안내는 포함합니다.
